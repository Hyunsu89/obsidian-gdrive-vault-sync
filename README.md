# GDrive Vault Sync

Obsidian vault 를 Google Drive 와 맞추는 플러그인. **아이패드(iOS)에서 동작한다.**

출장 중 아이패드만 들고 가서 회의록을 쓰고, 돌아와 합치는 용도로 만들었다.

## 설계 원칙

2026-10 에 다른 동기화 플러그인으로 Drive 에 중복 파일 73개가 생긴 일이 있었다.
그 원인을 구조로 막아 두었다.

1. **상태 파일을 두지 않는다.** `changesToken`·`lastSyncedAt` 같은 기기별 값을 저장하지
   않고 매번 Drive 를 직접 조회해 비교한다. 기기 사이에 덮어쓸 상태가 없으므로 어긋날 수가 없다.
2. **`.obsidian/` 을 건드리지 않는다.** 설정 폴더 동기화가 그 사고의 뿌리였다.
   설정으로도 풀 수 없게 코드에 고정했다.
3. **삭제하지 않는다.** 올리기는 새 파일만, 내려받기는 Drive 가 더 최신일 때만.
4. **권한을 좁게 받는다.** `drive.readonly` + `drive.file` 만 쓴다.
   `drive.file` 은 이 앱이 만든 파일 외에는 고치거나 지울 수 없어,
   "기존 노트를 건드리지 않는다"가 Google 쪽에서 강제된다.

## 단계

- [x] **0단계** 연결 확인 — 목록 조회만, 쓰기 없음
- [x] **1단계** 다운로드 — Drive → 로컬
- [x] **2단계** 업로드 — 새로 쓴 파일만 Drive 로
- [x] **3단계** 자동화 — 열 때 받기, 새 노트는 잠시 뒤 올리기
- [x] **노트 생성** — 업무회의 · 주간회의 · 업무일지 (PC QuickAdd 설정을 코드로 옮김)

## 설치

[BRAT](https://github.com/TfTHacker/obsidian42-brat) 으로 설치한다.
BRAT → `Add beta plugin` → `Hyunsu89/obsidian-gdrive-vault-sync`

## 설정

| 항목 | 설명 |
|---|---|
| 클라이언트 ID / 시크릿 | Google Cloud OAuth 클라이언트 (데스크톱 앱 유형) |
| Refresh token | `tools/auth.py` 로 발급 |
| 루트 폴더 ID | Drive 의 vault 폴더 ID |
| 제외할 최상위 폴더 | 쉼표 구분. `.obsidian` `.trash` 는 항상 제외 |

자격증명은 플러그인 설정(`.obsidian/plugins/.../data.json`)에만 저장되고,
`.obsidian` 은 동기화 대상이 아니므로 다른 기기로 넘어가지 않는다.

## 토큰 발급

```bash
python3 tools/auth.py url            # 주소를 PC 브라우저에서 연다
python3 tools/auth.py code <코드>     # 주소창의 code 로 토큰을 만든다
```

## 명령

### 동기화
- `지금 동기화 (받기 → 올리기)` — 리본의 새로고침 아이콘
- `Drive 다운로드 — 미리보기` / `— 실행`
- `Drive 업로드 — 미리보기` / `— 실행`
- `Drive 연결 확인` · `Drive 전체 스캔 (읽기만)`

### 노트 생성
- `회의록 만들기 — 업무회의` — 이름을 묻고 `10_회의록/아이웍스/{연도}/{YYMMDD} - {이름}.md`
- `회의록 만들기 — 주간회의` — `{YYMMDD} - 주간회의.md`
- `업무일지 만들기 — 이번 달` — `20_업무관리/일지/{연도}/{YYYY-MM}.md`

**이미 있는 파일은 덮어쓰지 않고 연다.** 월간 일지를 날려먹지 않기 위해서다.

## 자동화

| 설정 | 기본값 |
|---|---|
| 열 때 자동으로 받기 | 켜짐 (최소 간격 60분) |
| 새 노트 자동 올리기 | 켜짐 (60초 대기 후) |

자동으로 돌아도 하는 일은 수동과 같다 — 받기는 로컬에만 쓰고 로컬이 최신이면 건너뛰며,
올리기는 새 파일만 만든다. 기존 파일을 고치거나 지우는 경로가 코드에 없다.

## 옛 명령

- `Drive 연결 확인` — 인증과 최상위 폴더 목록 확인
- `Drive 전체 스캔 (읽기만)` — 재귀 조회로 파일 수·용량 집계

## 운영 규칙 — 삭제

**삭제는 전파되지 않는다.** 플러그인에 삭제 기능이 없다(설계 원칙 3).

한쪽에서만 지우면 다른 쪽에 파일이 남고, **남은 쪽이 다음 업로드 때 Drive 에 다시 올린다.**
업로드는 "로컬에 있는데 Drive 에 없는 파일"을 올리기 때문이다.

> 파일을 지울 때는 **PC 와 아이패드 양쪽에서 각각** 지운다.

회의록은 만들고 지울 일이 거의 없어 실제 부담은 작다.
자동 삭제를 넣지 않는 이유는, 그 경로가 생기는 순간 출장 중 쓴 회의록이
사라질 수 있는 길이 열리기 때문이다.

## 배경

2026-10 에 `google-drive-sync` 플러그인이 Drive 에 중복 파일 73개를 만들었다.
그 플러그인이 자기 상태 파일(`driveIdToPath`·`changesToken`·`lastSyncedAt`)을
vault 안에 두고 동기화해서, PC 와 아이패드가 서로의 커서를 덮어쓴 것이 원인이었다.

이 플러그인은 그래서 **판단에 저장된 상태를 쓰지 않는다.** 무엇을 받고 올릴지는
매번 Drive 를 직접 조회해 정한다. 자세한 경위는 `~/opsidian/DEPLOY.md` 6장.
